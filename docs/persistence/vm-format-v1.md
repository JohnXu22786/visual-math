# Visual Math `.vm` drawing format, version 1

A `.vm` document is UTF-8 JSON with `format: "visual-math-drawing"`, integer `version: 1`, a non-empty `name`, and a required `drawing` object. The current writer does not include an application version. Unknown keys under the optional top-level `extensions` object are retained on decode and encode. Unknown required versions, enum values, malformed required fields, and unknown object types are rejected before the page restores state.

The drawing object stores ordered formula rows with stable row IDs, exact editor source text, automatic/custom color selection and ARGB color, visibility, raw lower/upper domain expressions and endpoint inclusion, per-row parameter values, shared parameter values and slider ranges, active view and construction tool, active 3D polygon side count, 2D viewport bounds and axes/grid/zero/extrema display settings, and 3D camera, projection, axes, plane, grid, labels, and scene geometry/style. Scene objects have stable IDs and are tagged by object type. Point attachments and construction dependencies refer to those IDs so editable derived geometry can be rebuilt after reopening. Curves preserve sampled geometry and conic parameters; meshes preserve vertices, indices and normals. Derived plot data is recalculated from formula source when reopened.

Compatibility policy: readers accept version 1 and validate all fields that were required by the original v1 format. Fields added to v1 later are optional when reading older v1 files and receive the editor's defaults (empty formula domains with inclusive endpoints, default 2D display toggles, a six-sided active construction setting, generated object IDs, and no construction relationships); new writes include the complete current state. Optional vendor data belongs in `extensions`; writers must not discard it. A future incompatible required schema change increments `version` and requires an explicit migration before restore. A failed decode does not mutate the currently open drawing.

The built-in document store keeps documents in app-private files on native platforms and IndexedDB on web. Both backends provide list, read, atomic save, delete, and explicit overwrite for duplicate names. On first use after upgrading, existing drawings in the former `visual_math.documents.v1` preference index are copied into the new backend before the old blob is removed. Document blobs are not stored in preference keys after migration. The Files action lists documents and opens a selected drawing.

## Current v0.2 model limits

Formula-specific slider ranges are not exposed by the v0.2 editor; sliders are shared by parameter name and their values/ranges are persisted in the shared parameter map. All currently exposed formula domain, 2D display, 3D view, scene style/geometry, and construction relationship state is represented by v1.
