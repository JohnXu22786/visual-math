# Visual Math 0.3 Development Plan

`v0.3` is the planned MathSDK milestone. Track individual implementation tasks through related issues and pull requests. The preceding [v0.2 plan](v0.2.md) covers saving and reopening drawings.

## Goal

Make Visual Math straightforward for external applications to use as a MathSDK, including calling and rendering specific math display content without requiring the complete drawing screen.

## Scope

- Define a supported public SDK surface for embedding individual display components, with clear inputs and callbacks.
- Let consumers choose the specific content to render, such as a 2D graph, 3D geometry view, or formula display, without bringing in unrelated editing or navigation UI.
- Document package setup, the public imports, component selection, and representative embedding examples.
- Review the current exported widgets and models, then identify which should be stable public API and which are internal implementation details.

## Acceptance Criteria

- An external Flutter application can depend on the package and render a selected display component independently.
- The documented public API explains the required data, configuration, and events for each supported display type.
- A consumer can follow the package documentation to embed a display without using `MathDrawingPage` as the entire application screen.
- The supported API surface and compatibility expectations are stated for future package releases.

## Out of Scope

- Redesigning the drawing editor or adding app-level file navigation; drawing persistence is tracked in the v0.2 plan.
- Promising compatibility for every existing export before the public API review.
