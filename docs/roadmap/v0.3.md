# Visual Math 0.3：可组合的 Flutter SDK

## 目标和范围

让外部 Flutter 应用只引入需要的数学组件，用自己的界面和数据驱动它们，并获得交互结果；不要求使用 `MathDrawingPage`。v0.3 首先支持独立 2D 曲线画布、3D 几何画布，以及接入现有公式输入框、数学键盘、参数控件和 3D 工具栏。保留完整工作区作为可选入口。

界面组件是 Flutter widgets，不承诺在没有 Flutter 的纯 Dart 运行时渲染。现有公开数学模型可供宿主使用；是否能在纯 Dart 环境单独依赖，须另行核实，不能由本计划推定。v0.3 不依赖 v0.2，不涉及 `.v` 文件格式、应用内文件管理或跨应用序列化。

## 当前基线（main `b3afb39`）

| 能力 | 已有实现 | 与目标有关的缺口 |
| --- | --- | --- |
| 组件选择 | `lib/visual_math.dart` 导出 `MathCanvas`、`MathCanvas3D`、输入控件、工具栏及模型；`example/lib/main.dart` 已有独立 2D、3D 示例。 | 明确哪些接口纳入 v0.3 支持范围及其组合方式。 |

| 3D 数据 | `MathCanvas3DState.setObjects`、`setSurface`、`setCamera` 可在挂载后控制场景；有对象创建、场景和选择回调。 | 构造函数没有初始对象或相机输入；场景变化回调没有场景参数，宿主须自行读取状态。 |

| 样例与验证 | README 记录独立画布和宿主所有权；已有画布、3D 交互和工作区控制器测试。 | 现有测试的外部 SDK 覆盖尚未完整评估；需验证一个使用宿主数据持续更新的外部调用方。 |

以上是源码与文档检查结果，不代表本次已运行测试或验证全部平台。`MathCanvasWebView` 是独立的 JSXGraph 画布，依赖 CDN；本版本以纯 Flutter 画布为核心，保留其既有导出，不把它作为离线能力承诺。

## v0.3 对外契约

以下是本路线的设计目标；具体公开符号和签名在第 1 项确定，示意用途不能视为现有 API。

- **入口与兼容性：** 继续以 `package:visual_math/visual_math.dart` 为公开入口；外部应用不需要导入 `lib/src`。保留已发布的构造函数、State/`GlobalKey` 控制方式及 `dart_math.dart` 兼容导出。为支持的接口记录输入、输出、默认值、生命周期和平台要求；0.3.x 修订版本不主动破坏该契约，未来破坏性变更提供迁移说明。
- **宿主数据：** 2D 支持初始和后续更新公式、参数数值、视口；3D 支持初始和后续更新对象与相机。宿主自建 UI 时不需要包含项目的公式列表、键盘或页面导航。参数变化后，画布展示最新有效数据。
- **控制与所有权：** 为独立画布定义一致的公开控制入口，支持初始化、挂载后更新和读取当前状态。优先使用能随宿主数据更新的 widget 输入，必要时配合画布专用控制器；确定受控与非受控模式的优先级，避免两种来源互相覆盖。明确控制器单实例附着、解绑、销毁和挂载前调用的行为；不让组件释放宿主拥有的控制器。
- **事件与错误：** 为必要的视口、场景、选择变化提供带有足够数据的公开反馈，区分宿主设置数据和用户交互导致的通知，避免双向绑定循环。无效公式、非有限参数或非法视口通过明确的错误机制反馈，不以静默成功代替；说明是否保留上一个有效图像。
- **组合：** 宿主可自行实现输入和工具，也可把已有公式输入框、键盘、参数控件或工具栏连接到画布。文档说明每个部件需要的控制器、状态、回调及资源所有权。对话框、主题、手势和本地化的支持以公开配置及平台实际能力为准。
- **平台与网络：** 核心 2D/3D Flutter 画布不要求网络。记录 README 已列平台上的编辑器回退和 WebView 差异；构建通过、运行时支持和经过实际交互验收分别记录，不把某个平台构建成功等同于运行时验证。

## 执行顺序

### 1. 契约和现状清单

**依赖：** 无。核对公开导出、两个画布的可设置数据与回调、现有控件、示例及最接近的测试；将当前行为和拟新增行为分开。确定受支持的类型、输入更新、错误、状态归属、控制器生命周期和兼容策略，并给出迁移路径。

**完成标准：** 在仓库中记录可供实现和外部调用方使用的 API 契约与平台矩阵；所有提议的签名与现有实现明确区分。

### 2. 独立画布的宿主数据接口

**依赖：** 第 1 项。补齐 2D 公式、参数和视口的初始值及后续更新；补齐 3D 对象和相机的初始值及后续更新；提供必要的状态读取、事件和错误反馈。复用现有渲染和模型，保留现有 `GlobalKey` 与完整工作区用法。

**完成标准：** 外部应用只通过公开入口即可控制各自独立的 2D、3D 画布；宿主更改数据后画面反映最新有效状态，不依赖完整页面。

### 3. 控件组合和宿主界面

**依赖：** 第 1、2 项。核对公式输入框、键盘、参数控件和 3D 工具栏的状态及回调，补齐实现目标所需的公开连接点；提供宿主自建控件及选用现有控件的组合示例。尽量复用现有组件，不重复建立已可独立使用的画布。

**完成标准：** 宿主可独立选择画布及控件，按文档建立连接，也可用自己的输入和按钮替代项目控件。

### 4. 外部调用方验证和发布准备

**依赖：** 第 2、3 项。复用现有独立示例，必要时增加只导入公开包入口的独立 consumer fixture；补齐 API 文档、迁移说明、changelog、版本和发布材料。根据仓库工具链运行必要的静态分析、针对性测试及 consumer 构建，并记录实际平台结果。发布到 pub.dev 或创建正式 release 需另行明确，不由此路线文档本身触发。

**完成标准：** 外部调用方按文档完成下列场景，结果与公开契约一致；发布材料列出已验证的平台与已知限制。

## 验收场景

1. 宿主自行输入 `a`、`b` 并传入 `y = a*x + b`；更改数值后图像更新，不引入 `MathDrawingPage`。
2. 宿主以自己的按钮设置和更新 3D 对象及相机，并能获取场景或选择变化。
3. 同页两个画布使用不同数据和控制入口；更新、解绑或销毁一个不会改变另一个，也不释放宿主资源。
4. 无效公式、非有限数值、非法视口以及挂载前或销毁后的控制调用按照已记录契约处理；宿主收到可理解的结果。
5. 宿主既可连接现有输入控件，也可只使用自建 UI；交互回调不会因宿主回写形成无限循环。
6. 现有完整工作区、已发布入口和 `GlobalKey` 调用保持兼容；公开 API 文档及示例不依赖 `lib/src` 导入。
7. 按实际支持矩阵执行针对性自动化验证和外部 consumer 构建；明确区分通过、失败和未验证的平台。

## 依赖与边界

以上工作按 1 → 2 → 3 → 4 推进；第 1 项发现已满足的能力时直接复用。v0.2、持久化、重新设计完整编辑器、独立公式渲染器和 CDN 画布离线化均不属于本计划。执行中如发现目标要求新的公开能力或不兼容变更，应先记录影响与迁移方案，再调整计划。
