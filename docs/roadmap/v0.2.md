# Visual Math 0.2 开发计划

`v0.2` 聚焦绘图的应用内保存与重新打开。各项工作通过相关 issue 和 pull request 跟踪；可选用 GitHub milestone 汇总并链接本计划。

## 目标

让用户能将绘图保存在应用内，并在之后从 Files 页面重新打开。

## 里程碑

### 1. 确定 `.v` 持久化约定

**依赖：** 无。

**范围：** 在实现前由产品和维护者明确并记录待定决策：文件 schema 与版本策略；哪些绘图状态需要保存；应用内存储位置；命名、重名及覆盖行为。此里程碑只要求作出并记录决定，不预设具体答案。

**退出条件：** 上述决策已记录在可供实现任务引用的约定中，并说明未支持或不可保存的状态如何处理。

### 2. 保存绘图至应用内存储

**依赖：** 里程碑 1。

**范围：** 按已确定的约定，将当前绘图保存为应用内 `.v` 文件。

**退出条件：** 用户可保存绘图；文件写入约定的应用内位置，且保存结果符合已确定的命名和重名/覆盖规则。

### 3. Files 导航与重新打开

**依赖：** 里程碑 2。

**范围：** 在应用导航中提供 Files 页面，列出已保存文件，并支持选择和重新打开。

**退出条件：** 用户可从导航进入 Files，看到已保存文件，选择文件后查看对应绘图。

### 4. 往返与无效文件验收

**依赖：** 里程碑 1 至 3。

**范围：** 验收保存后重新打开的往返结果，以及不支持版本和损坏 `.v` 文件的处理。

**退出条件：** 支持的绘图状态经保存和重新打开后符合约定；不支持或损坏的文件得到可理解的失败处理，且不会被当作有效绘图打开。

## 范围边界

- 仅覆盖应用内保存、Files 列表和重新打开。
- 导入、导出、重命名和删除不属于本版本承诺范围。
- 文件格式、保存状态和重名行为须先按里程碑 1 决定；本计划不代替这些产品决策。
